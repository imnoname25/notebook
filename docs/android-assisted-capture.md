# Android-assisted Capture v1

## Android-first Content Capture — этап B

Новые черновики ссылок запускают задачу WorkManager сразу после записи Intent на диск. Пользователь может сохранить ссылку, пока телефон получает метаданные. Готовый результат и двоичная обложка хранятся в приватном черновике. После подтверждения сервером отправка использует тот же снимок и UUID черновика. При повторном входе незавершённая отправка возобновляется для того же сервера и аккаунта. Подтверждённые ссылки остаются на сервере, даже если локальное подтверждение доставки превью не пришло.

Новый Android-клиент добавляет `X-Notebook-Device-Capture: 1` к обычному `POST /api/saved-items`. Сервер сохраняет ссылку сразу и откладывает обе очереди на 90 секунд. `PUT /api/saved-items/[id]/device-capture` принимает JSON версии 1 и, при наличии, поле `cover` в multipart. Запрос должен принадлежать владельцу и использовать Idempotency-Key исходного сохранения. Полное превью закрывает очередь метаданных, а для распознанного видео, социальной публикации или товара не требуется очередь статьи. Для обычной ссылки сервер может получить недостающую статью в соответствии с настройкой автоизвлечения. После срока ожидания срабатывает обычный fallback. Результат, пришедший позже, сохраняется по тем же правилам приоритета.

Сохраняются оригинальный URL и отдельный canonical с проверкой хоста или ID ролика, тип материала, автор, дата публикации и происхождение доступных полей. Пользовательский заголовок, теги и вложения сохраняются. Полное извлечение статей на Android относится к этапу C. Прежний `device-preview` поддерживается как для уже сохранённых карточек, так и для старого сервера.

Миграция `202611150001_android_first_capture` добавляет необязательные данные и срок ожидания в `SavedItem`. Для новых полей захвата используется архив v9. v7 и v8 продолжают записываться для своих наборов данных и читаться новым импортёром. Срок ожидания, ключ операции и ошибки доставки не переносятся в архив. Для восстановления v9 нужен совместимый образ. SQL dump вместе с каталогом uploads сохраняет полные данные при смене образа.

### Проверка этапа B на телефоне

1. На отдельном сервере примените миграции и подключите локальную debug-сборку. Поделитесь публичной ссылкой YouTube или Shorts. Сохранение ссылки должно работать сразу. После появления обложки откройте карточку в браузере на другом устройстве.
2. Повторите с включённым и выключенным Android VPN. При недоступном источнике проверьте сохранение оригинальной ссылки и переход к серверному fallback. Проверку на телефоне проводите с уже настроенным пользовательским VPN.
3. Повторите отправку текста, PDF и нескольких изображений. Для ссылки с ручным названием выключите сеть до отправки, перезапустите приложение и включите сеть. Проверьте одну карточку, сохранённое имя, теги и вложения.

## Android Article Capture — этап C

Android использует уже полученный HTML для метаданных и статьи. В локальную копию входят заголовки, абзацы, списки, цитаты, ссылки и иллюстрации в порядке документа. Служебные элементы и страницы доступа отбрасываются. На документ выделено до 512 КиБ, на захват HTML-статьи — до 36 секунд. Иллюстрации ограничены восемью файлами, 2 МиБ на файл и 8 МиБ суммарно. Если нужная иллюстрация недоступна или материал превышает лимиты, Android сохраняет метаданные и оставляет обычное серверное извлечение доступным.

Запрос `device-capture` версии 1 принимает опциональный объект `article` с блоками и манифестом изображений. Multipart передаёт бинарные части `image.<key>`, где ключ соответствует блоку. Сервер проверяет комплектность, декодирует файлы и сохраняет приватные WebP через существующие записи `SavedArticleImage`. Сохранение статьи и файлов атомарно. Готовая копия закрывает автоматические задания статьи и метаданных, если телефон прислал результат до начала fallback. Существующая копия сохраняется при автоматическом захвате. Предыдущий сервер принимает повторную отправку метаданных через тот же API, если отклоняет новый объект статьи.

В базе и архивах используется прежний формат блоков SavedArticle v1/v2. Иллюстрации попадают в архив как существующие portable attachments. Версия архива остаётся v9 при наличии метаданных Android-first, а восстановление v7/v8 поддерживается.

Для ручной проверки добавьте доступную статью с иллюстрациями через Share Target, затем откройте её в Notebook с другого устройства при недоступном оригинале. Проверьте порядок блоков и изображений. Повторите с Pikabu, DNS Club и VK. Для HTTP 401/403 или технической заглушки должна сохраниться ссылка без новой статьи.

## Протокол превью предыдущей версии

Share Target сохраняет черновик в существующей очереди Android. Когда Notebook подтверждает создание карточки, WorkManager получает задачу для её идентификатора. Задача через текущую сессию проверяет выбранный сервер и владельца карточки. При временном сбое сеть проверяется повторно до трёх раз. Подтверждённая карточка доступна сразу после отправки ссылки.

Для YouTube Android пробует официальный oEmbed. При недоступности он передаёт Noembed канонический идентификатор ролика. Явный отказ доступа завершает попытку. Для остальных источников Android читает Open Graph и Twitter Card и скачивает выбранную обложку. Запросы источников идут через системную сеть Android, включая доступный приложению VPN. Они выполняются отдельным HTTP-клиентом без сессии Notebook. Задача принимает публичные адреса, проверяет редиректы и ограничивает объём данных.

Сервер принимает проверяемые текстовые поля и двоичные данные обложки через `PUT /api/saved-items/[id]/device-preview`. Нормализованная WebP хранится в `/data/uploads` и доступна владельцу через `/preview`. Текст с Android заполняет отсутствующие поля, а источник уже подтверждённых полей сохраняется. Первая принятая локальная обложка сохраняет приоритет при следующих попытках. Исходную ссылку, ручной заголовок, теги и вложения продолжает обслуживать обычный Saved Items API.

## Миграция и архивы

Миграция `202611140001_saved_item_device_preview` добавляет признак происхождения отдельных полей, ссылку на Upload и тип операции идемпотентности. Существующие записи получают пустой список полей и пустую ссылку на обложку. Тестовый сервер применяет миграцию через `prisma migrate deploy`.

Архив без данных Android сохраняется в v7. Когда архив включает поля или обложку с Android, Notebook пишет v8 и связывает файл через portable key. Импортер читает v1–v8. Для восстановления v8 нужен образ с этой функцией. Предыдущий образ на мигрированной БД читает ссылки и текстовые поля. Он показывает только серверное превью и не может сохранить связь с локальной обложкой при экспорте в v7. Для отката с сохранением этих данных используйте SQL dump вместе с каталогом uploads или архив v8 с совместимым образом.

## Проверка на телефоне

1. Поднимите отдельный тестовый сервер на этом коммите и примените миграцию. Установите локальный debug APK с совместимой подписью либо используйте отдельное тестовое устройство. Войдите на тестовый сервер.
2. Включите используемый вами Android VPN и убедитесь, что он включает приложение Notebook. Поделитесь публичным YouTube-роликом. Подтвердите сохранение в Share Target и откройте карточку. Дождитесь заголовка, автора и обложки. Повторите при обычном подключении и при недоступном CDN.
3. Поделитесь ссылкой без сети. Откройте очередь, затем восстановите связь. После отправки проверьте, что в «Сохранённом» появилась одна карточка. Прервите ручное обновление через «Отменить обновление» и повторите.
4. В меню старой карточки выберите «Обновить превью с устройства». Проверьте, что ручной заголовок, теги, архивный статус и вложения сохранились. Откройте ту же карточку в обычном браузере и проверьте отображение обложки.
5. Проверьте передачу простого текста, PDF и изображения. На тестовом сервере проверьте восстановление исходного архива v7 и нового архива с Android-обложкой.
