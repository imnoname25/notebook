# Sticker Board 4.0 — Freeform Canvas

## Подтверждённые причины

В предыдущей реализации одновременно действовали три независимых ограничения: `sticker-editor-lines` имел `max-h-64` (256 px) и свою прокрутку; `LineInput` ограничивал высоту textarea значением 144 px; обычный текст использовал `rows=5`. Высота строк пересчитывалась только при изменении текста, поэтому сужение карточки не увеличивало её достаточно для перенесённых строк. Внешний flex-контейнер рос, а содержимое оставалось внутри прежних ограничений.

В Chrome до исправления у длинного пункта измерено `clientHeight=144`, `scrollHeight=308`, у списка — `max-height:256px`. Это воспроизводит вложенные скроллбары и неиспользованную площадь.

Карточки ранее располагались через Grid, затем flex-wrap / sortable rect strategy; оба способа автоматически переставляли соседей и не описывали свободное пространство.

## Единая область содержимого

Карточка на desktop — flex column с заданными width/height. Заголовок, статус сохранения и footer не сжимаются; `.sticker-content-scroll` занимает оставшееся пространство, имеет `min-height:0`, `min-width:0` и единственную вертикальную прокрутку. Горизонтальный overflow содержимого запрещён.

Редактор обычного текста и строки чек-листа больше не ограничиваются 144/256 px. Textarea растут по содержимому, `ResizeObserver` пересчитывает их при изменении ширины, без замены DOM-элемента или сброса selection. Длинные слова и URL переносятся. У textarea `overflow:hidden`, при этом проверяется, что scrollHeight не превышает clientHeight: текст не скрывается за этим правилом. Короткий обычный текст получает растягиваемое поле во всю оставшуюся площадь.

В обеих темах после расширения короткой карточки до 640×700 px получены размеры области содержимого **608×576 px**, textarea **608×532 px** (остальные 44 px занимает действие чек-листа). У длинного пункта после переноса: `clientHeight=524`, `scrollHeight=524`, собственный overflow отсутствует. Минимальный размер 260×260 и стандартный 320×340 также проверены.

Quick Capture имеет собственную единую ограниченную область прокрутки. Он не наследует размеры или координаты доски. Изменение размера карточки не переключает редактор и не теряет введённый текст/курсор.

## Свободная доска

Только самостоятельный раздел «Стикеры» при доступной ширине от 1200 CSS px использует абсолютное позиционирование внутри canvas. Основной механизм размещения не использует Grid/Masonry или сортировку соседей.

Каждая карточка имеет `{x,y,width,height,z}`. Координаты отсчитываются от canvas, а не от окна. Canvas расширяется до границ карточек с запасом, прокручивается внутри рабочей области, не расширяя страницу. При изменении sidebar или viewport сохранённые координаты не пересчитываются. Координаты ограничены 0–30000 px; размер — 260–640 по ширине и 260–800 по высоте. Уменьшение окна оставляет карточки доступными через прокрутку и «Найти стикер».

Заголовок карточки — поверхность перемещения. Обычное нажатие открывает редактирование названия; движение от 5 px начинает drag. Textarea, чекбоксы, меню и input названия не являются drag activator. Resize использует отдельный правый нижний маркер. Оба жеста используют pointer capture; координаты учитывают прокрутку доски. У края есть простая автопрокрутка во время движения. Жест не выделяет текст.

Клавиатура: фокус на заголовке, стрелки — сдвиг на 10 px, Shift — на 40. На resize marker стрелки меняют размер с теми же шагами; Home или двойное нажатие возвращают стандартный размер только этой карточке, сохраняя координаты. Действия описаны через aria-description. На coarse pointer у desktop-маркера увеличенная touch target.

Выбор карточки поднимает её над остальными. Z ранги каждый раз нормализуются до 1…N, не растут без ограничения. Разрешены произвольные расстояния и частичное/полное перекрытие. «Найти стикер» поднимает выбранную карточку, прокручивает к ней и ставит фокус на заголовок; это также способ извлечь полностью закрытую карточку. Активная карточка имеет спокойный outline. Canvas изолирует собственные stacking contexts, чтобы карточки не перекрывали поиск и меню приложения.

«Упорядочить стикеры» — явное действие: предсказуемая раскладка по существующему порядку (закреплённые сначала, затем sortOrder/id), без перекрытия и без изменения размеров. Доступно «Отменить упорядочивание». Последующий drag/resize отменяет этот Undo, чтобы не откатывать более позднюю геометрию. Загрузка доски не упорядочивает существующие координаты.

Отсутствующие координаты получают свободное место без перемещения соседей. Существующие индивидуальные размеры 3.3 читаются как legacy preferences и переносятся в новую геометрию. Неизвестные размеры используют стандартные. Архивированные карточки сохраняют свою геометрию, но не занимают места при размещении новых видимых карточек. После создания через Quick Capture карточка появляется без перекрытий, по возможности; при открытой доске она раскрывается в рабочей области.

## Разделение данных и хранения

- **Sticker Content:** прежний QuickNote API и StickerSaveStore — title/body/checklist/color/pin/status. Никакой копии для другого экрана.
- **Sticker Board Layout:** локальные настройки этого браузера, ключ `notebook:sticker-board:v4:<encoded userId>`, version 1, map по noteId. Только геометрия, без текста или токенов. Zod валидирует координаты, размеры, ранги и число записей. Старые size keys читаются для совместимости.
- **Sticker Preview:** прежний TodaySticker / StickerChecklistPreview без canvas layout, drag или resize.

Проверена существующая `/api/account/preferences`: там фиксированные scalar user settings, нет layout JSON. Выбран совместимый с 3.3 локальный механизм без расширения UserSettings, API и схемы БД. На другом устройстве та же заметка получает собственное расположение. Размеры/координаты не синхронизируются между браузерами и не входят в export/backup. Logout не удаляет preference, очистка данных сайта сбрасывает геометрию. Разные аккаунты имеют разные ключи. В нескольких одновременно открытых вкладках этого браузера действует последнее записанное расположение; совместное редактирование доски не вводилось.

Во время drag/resize геометрия меняется только в React state/ref. Конечные координаты записываются после завершения жеста, а не при каждом движении. Ранг может записываться отдельно при выборе. Синхронный current ref исключает перезапись последнего жеста предыдущим React snapshot. Отмена жеста не фиксирует промежуточные координаты. Ошибка localStorage отображается пользователю, состояние в памяти остаётся доступным. Никаких запросов сохранения содержимого или записей истории от перемещения нет.

## «Сегодня», Capture, Fold

«Сегодня» сохраняет компактную адаптивную сетку preview. В нём нет абсолютных координат, свободного перетаскивания, resize marker или команды упорядочивания. Исправлен конфликт `block` с `line-clamp-2` для длинного обычного текста, карточки не растягиваются до высоты соседнего preview. Чекбоксы сохраняются через того же writer. Нажатие preview открывает доску и поднимает конкретный стикер, без изменения его координат/размеров.

Ниже 1200 px самостоятельная доска становится вертикальным списком. Desktop style не применяется, layout commands скрыты, редактор и чек-листы остаются полноценными. Мобильная загрузка не создаёт и не перезаписывает desktop-геометрию; после расширения окна она восстанавливается. Режим выбирается по доступной ширине, не по user-agent или модели Fold. «Сегодня» и Capture не превращаются в canvas ни на одном breakpoint.

## Проверки и ограничения

- `npm run check`: version check, lint, typecheck, unit tests, production build. Пять новых layout unit tests проверяют non-overlap seed, legacy sizes, неизменность соседей, ограниченные z ранги, explicit arrange и account isolation.
- На отдельной новой PostgreSQL 18 БД применены существующие миграции и выполнены **4 quick-note integration tests**: ownership, duplicate/tags, archive/restore, stale text/checklist/convert. Production БД не использовалась.
- Настоящий Chrome с реальными компонентами и синтетическим API, обе темы: до/после с одинаковым содержимым, минимальный/стандартный/увеличенный размер, реальные client/scroll размеры textarea, заполнение площади, длинные URL и кириллица, сохранение focus/selection при resize, drag мышью/клавиатурой, перекрытие, z/front recovery, reload, arrange/Undo, Today toggle → board с прежней геометрией, открытие полного стикера из preview, 360/840 px и возврат на desktop, Capture и размещение нового стикера, быстрый поиск над canvas. Отчёт и скриншоты: локальный `test-results/sticker-board-4/index.html`, `report.json`.
- Существующий HTTP E2E создания нескольких стикеров сохранён. Добавлены два сценария в `e2e/sticker-board.spec.ts`; checklist E2E обновлён для редактирования заголовка. Playwright обнаруживает сценарии. Полный HTTP E2E не выполнен: ранее автоматическая проверка запретила запуск локального Next.js с тестовой конфигурацией (`blocked by policy`, без дополнительной причины). Браузерный fixture не заменяет HTTP/auth/Prisma boundary.
- Физический Fold, Android WebView и нативная touch-клавиатура не проверены. Бесконечный canvas, zoom, multi-user или realtime не добавлены. Для очень больших досок действуют границы координат и локального storage; содержание остаётся в PostgreSQL независимо от layout.
