## Round-trip и сохранность изображений

- Полный экспорт v7 перенесён другому пользователю. Проверены новые ID материалов и Upload, исходный пустой `title`, происхождение `share`, `sharedTitle`, метаданные сайта, текст, теги, статусы, даты и архивность.
- Содержимое статьи и версия блоков совпали с архивом. Пользовательское вложение и изображение статьи переназначены на корректные Upload нового владельца.
- Байты локального WebP после импорта, чтения приватным API и restore совпали с исходным буфером. SHA-256 проверен на экспорте и при подготовке импорта.
- Изображение с отсутствующим файлом сохранено с прежними ключом, URL, позицией и `attachmentKey=null`. Файл не выдумывается.
- В offline-проверке `fetch` отклонял любые обращения. Импорт и чтение статьи не вызвали `fetch`. У импортированного материала отсутствует SavedArticleJob и нет ожидающего задания метаданных.
- Экспорт отдельного блокнота исключает глобальные Saved Items и их изображения.

## Operational restore и безопасность

- Restore v7 заменяет Saved Items, статьи и изображения. Предварительно запущенное старое задание worker после восстановления отклонено по прежнему ID и аренде.
- Восстановление через административный сервис сначала создаёт v7 safety backup. Проверены регистрация, размер, SHA-256, содержимое safety backup и восстановление более позднего пользовательского изменения из неё.
- HTTP restore требует сессию администратора, корректный origin и подтверждение `RESTORE`. Повреждённый архив отклонён до создания safety backup и изменения данных.
- Неправильный хеш, отсутствующий файл, дубли ключей, неизвестный Upload, недопустимый MIME, некорректные блоки и неподдерживаемая версия отклонены. Пересчитанный SHA-256 повреждённого raster не обходит декодер.
- Ошибка транзакции после записи файлов и принудительный разрыв её PostgreSQL-соединения оставили прежние строки и набор файлов. Ошибка записи на диск также сохранила исходное состояние. В существующем наборе проверен ENOSPC после первого скопированного файла с сохранением safety backup.
- Проверены одновременный экспорт и удаление материала с очисткой Upload, а также экспорт во время публикации новой версии статьи worker. Архив сохранил полную предыдущую версию вместе с файлами.
- Для v1–v5 проверены импорт и restore с сохранением существующих Saved Items. Для старого v6 и v6 этапа A проверены прежняя семантика замены и происхождение заголовка. Обязательный SHA-256 остаётся границей v6.

## Исправления по результатам проверок

1. Разделены пороги Saved Items, обязательных хешей и статей. Во все схемы версий добавлено явное сохранение v6.
2. Устранена постановка импортированных URL без метаданных в очередь фоновой загрузки.
3. Shared BlockNote schema вынесена в отдельный browser-safe модуль. Это устранило попадание Node.js network imports в клиентский bundle через расширенную схему архива.
4. Декодирование WebP переведено на буфер, чтобы кэш libvips не удерживал файлы Windows при очистке restore.
5. Актуализированы тесты с жёстким ожиданием writer v6, при этом оставлены явные архивные фикстуры v6.
6. Добавлена диагностика неуспешной компенсационной очистки файлов без вывода персональных данных.

Первый общий PostgreSQL-прогон выявил неподходящую locale C для проверок русского поиска. Итоговый прогон выполнен на новой ICU-БД. При первом HTTP-прогоне флаг происхождения заголовков различался у сервера и тестового процесса. После выравнивания конфигурации повторный прогон прошёл. Автоматическая проверка безопасности отклонила фоновый Start-Process. HTTP-сервер успешно запущен в управляемой консольной сессии и затем остановлен.

## Оставшиеся риски и границы проверки

- Docker/volume round-trip требует контейнерной приёмки, Docker в текущей VM отсутствует.
- Полное отключение питания и аварийное завершение процесса не воспроизводились. Прерывание соединения БД проверено. При process crash могут остаться незарегистрированные файлы, для которых предусмотрены storage audit и штатная очистка. При неизвестном commit или недоступной БД файлы сохраняются до проверки.
- При отказе удаления прежних файлов после commit восстановленные данные остаются в БД, операция сообщает об ошибке и требует проверки хранилища. Safety backup сохраняется.
- Длительный экспорт удерживает блокировку файлов пользователя и может задержать изменение материала, worker или очистку. Действует существующий timeout транзакции 120 секунд.
- Прогон выполнялся в рабочем дереве с сохранёнными сторонними изменениями UI. Они не входят в коммит этапа D. Схема и сервисы архива проверены отдельными новыми тестами.
- В журнале интеграционных тестов остаётся предупреждение pg о параллельных запросах одного клиента. Все итоговые проверки завершились успешно.

Для приёмки восстановите v7 архив на изолированном экземпляре, заблокируйте доступ к исходным сайтам и откройте архивную статью с локальными изображениями. Дополнительно проверьте повторный запуск контейнера с прежними persistent uploads и PostgreSQL, когда Docker-среда будет доступна.
