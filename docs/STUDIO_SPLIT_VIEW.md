# Studio 4.1 — архитектура Split View

До реализации проверены `NotebookApp`, `useDocumentTabs`, чистая модель вкладок,
`EditorSaveQueue`, `RichTextEditor`, exact match navigation и responsive CSS.
Исходная система предполагает один активный редактор: глобальный controller ref,
один activePageId, общие события сохранения/scroll и CSS Highlight registry.
Просто смонтировать второй EditorPane небезопасно.

Выбрана архитектура двух существующих tab controllers с отдельными session keys,
очередями переходов и activePageId. Координатор рабочего пространства хранит
принадлежность вкладки панели, активную панель, документы и registry контроллеров
по documentId. Открытие уже принадлежащего другой панели ID переводит фокус туда,
не создавая второй writer. На экране не более двух BlockNote.

Каждый writer продолжает использовать свой page.id, revision и page-service.
Переход/закрытие ожидает сохранение только заменяемого документа. Выход из рабочего
пространства и logout ожидают оба writer. При ошибке редактор с черновиком остаётся
смонтированным. Перед переносом/слиянием панелей проверяются затронутые сохранения;
общая короткая блокировка относится только к операции изменения раскладки.

Редакторы рендерятся с ключом documentId: изменение пропорции и временное скрытие
панели не создают новый экземпляр. На узком viewport видна только активная панель;
вторая остаётся смонтированной до безопасного закрытия Split View. Настройка split,
пропорция, активная панель и tab metadata сохраняются по аккаунту, без содержимого.

## Поведение и хранение

Включение Split View открывает пустую соседнюю панель. Новые переходы из списка, поиска,
Today и ссылок направляются в активную панель. «Открыть справа» доступно в меню страницы.
Уже открытый ID активирует своего владельца; перенос выполняется явно через меню вкладки
или native desktop drag-and-drop. Резервирование владельца действует и во время загрузки,
поэтому два одновременных открытия не создают двух writers одного ID.

Каждая панель сохраняет собственные preview/permanent/pinned-вкладки. Левая использует
прежний `tabSessionKey(userId)`, правая — тот же ключ с суффиксом `:right`.
`notebook:split-workspace:v1:<encodedUserId>` содержит только split/active/ratio.
Содержимое документов в localStorage не записывается. Это настройки данного браузера,
между устройствами они не синхронизируются. Ограничение — 100 уникальных открытых документов.
Прямой URL имеет приоритет над последней активной панелью. Back/Forward открывают документ
у его владельца. Недоступные вкладки исключаются существующим механизмом восстановления.
При закрытии Split View вкладки объединяются без дубликатов и сохраняют pinned-группу;
выбранный редактор становится единственным, сохраняя свой экземпляр и черновик.

Перед изменением структуры отменяются устаревшие намерения навигации и ожидается завершение
текущих переходов. Пока выполняется перенос, редактирование временно приостановлено.
Ошибка flush отменяет операцию: исходный редактор остаётся доступен для повторной попытки.
Обычные переходы и сохранения соседней панели имеют отдельную очередь. Save callbacks,
контроллеры, revision и remount после restore адресованы конкретному pageId.
JSON документов, page-service, серверные проверки ownership и API не изменены.

## Фокус, поиск и адаптивность

Ctrl/Cmd + Alt + ←/→ выбирают панель и восстанавливают фокус её BlockNote.
Ctrl/Cmd + Alt + Enter переносит документ в соседнюю панель; с Shift закрывает Split View.
Кнопки и меню являются альтернативой сочетаниям, которые может перехватывать ОС/браузер.
Ctrl/Cmd+S адресован только активному редактору. Ctrl/Cmd+F остаётся штатным браузерным поиском.
Перенос мышью работает на desktop; на touch следует использовать меню вкладки.
Разделитель доступен по Tab: ←/→ меняют долю на 2%, Home и double-click возвращают 50/50.
Пропорция записывается после завершения жеста, а не на каждом pointermove.

Две видимые панели разрешены при ширине самой рабочей области от 760 CSS px;
минимальная ширина редактора — 360 px. Учитываются реальные ResizeObserver-размеры,
а не модель устройства. Split не включается автоматически. На узком экране видна одна
активная панель, переключатель соседней остаётся доступен, сохранённая раскладка не меняется.
Два уже открытых редактора остаются смонтированными: скрытие при resize не теряет selection,
черновик или pending save. Для остальных вкладок экземпляры BlockNote не создаются.

Exact Match получает pageId и действует только в соответствующей панели. CSS Highlight
имена уникальны по pageId. События раскрытия вложенных блоков также scoped по pageId,
поэтому совпадающие block IDs двух документов не раскрывают соседний документ.
Глобальные события сохранения, scroll и suggestion overlays учитывают активность панели.

## Ограничения проверки

Chrome запускался с перехватом HTTP-запросов и настоящими серверными сервисами/Prisma,
а не с работающим Next HTTP server. Это browser integration, а не полноценный HTTP E2E:
middleware, cookies и auth boundary этим запуском не проверены. Запуск локального Next
server ранее отклонён автоматической проверкой инструментов (`blocked by policy`);
причина подробнее не предоставлена. Штатный Playwright spec только проверен на обнаружение.
Физический Android/Fold, реальная клавиатура устройства и профилирование heap/CPU не выполнены.
Проверка производительности ограничена числом редакторов и отсутствием remount при resize.
Production, Docker, Android APK, серверная конфигурация и схема PostgreSQL не изменялись.

На физическом Fold нужно открыть A/B на desktop, изменить обе заметки, свернуть окно до
внешнего экрана, переключить активную панель, раскрыть устройство, проверить обе заметки,
экранную клавиатуру и восстановление после reload. Эмуляция Chrome не заменяет эту приёмку.
