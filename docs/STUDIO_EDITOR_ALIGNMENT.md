# Studio — выравнивание документа на широком экране

## Подтверждённая причина

На базе `625e86f` реальный Chrome показал auto margins у `.notebook-editor .bn-editor`.
Правило в `src/app/studio.css` ограничивало ширину этого DOM-элемента через
`max-width: calc(var(--notebook-reading-width) + 2 * var(--studio-reading-gutter))`,
но одновременно задавало `margin-inline: auto`. Вся колонка центрировалась в оставшемся
после двух навигационных панелей пространстве. Заголовок и теги центрировались отдельно.

Например, при 1750 px рабочая область имела ширину 1190 px, `.bn-editor` — 848 px,
каждый auto margin — 171 px, внутренний padding — 56 px. Итого до текста было 227 px.
`globals.css` задаёт исходные нулевые margins; именно более специфичное Studio-правило
их переопределяло. Это не пользовательские отступы цитат/вложенных списков.

## Исправление и настройка

По умолчанию start margin равен нулю, end margin — auto. В трёхпанельном режиме внутреннее
поле равно `clamp(2rem, 2.5vw, 3rem)` — 32–48 px при стандартном размере шрифта.
Лимит текста сохранён: normal 46 rem, narrow 40 rem, wide 64 rem. Заголовок, статус,
теги и BlockNote используют одну колонку и общие margins. В focus mode колонка центрируется;
его более специфичные старые правила также учтены, поэтому заголовок остаётся на линии текста.
Вложенность и пользовательское форматирование блоков не переписываются.

Для Studio в **Настройки → Оформление → Выравнивание документа** доступны «Слева» и
«По центру». Выбор применяется сразу, без сохранения страницы или обращения к API.
Он доступен обычному пользователю и администратору, хранится в этом браузере под ключом
`notebook:document-alignment`. Значение валидируется Zod; отсутствующее/неверное — «Слева».
Поддерживаются обновления в другой вкладке и fallback в памяти при запрете localStorage.
Настройка не меняет текстовое выравнивание абзацев. Старые темы сохраняют прежние правила.

## Координаты до и после

Измерения `getBoundingClientRect()` и DOM Range в headless Chrome; единицы — CSS px.
Обе темы дали одинаковые координаты. Normal width, масштаб 100%, стандартный шрифт 16 px.
Начало текста измерено на первом абзаце; заголовок и теги совпали с ним с точностью <2 px.

| Окно | Правый край списка X | Текст X до | Текст X после | Отступ до → после |
| --- | ---: | ---: | ---: | ---: |
| 1440×1080 | 532,78 | 618,39 | 568,78 | 85,61 → 36 |
| 1750×1080 | 560 | 787 | 603,75 | 227 → 43,75 |
| 1920×1080 | 560 | 872 | 608 | 312 → 48 |
| 2560×1080 | 560 | 1192 | 608 | 632 → 48 |
| 393×873 | список скрыт | 16 | 16 | поле 16 → 16 |
| 840×1080 | 252 | 276 | 276 | 24 → 24 |

Дополнительно при 1920 px: явное «По центру» начинает текст на X=872,
focus — на X=592 (без боковых панелей). В narrow/normal/wide при «Слева» текст начинается
на X=608; ширина контейнера с padding — соответственно 736/832/1120 px.

## Проверки и ограничения

Скриншоты одинакового документа до/после находятся в `test-results/studio-alignment/`
(ignored): `before-{theme}-{width}.png`, `after-{theme}-{width}.png`, а также center/focus.
В `before.json` и `after.json` сохранены точные координаты, computed margins, padding,
max-width и SHA-256 исходного BlockNote JSON. Hash до/после совпадает; записи Page content
при проверке отсутствуют. Обычное открытие страницы вызывает существующую запись recent.

Chrome действительно запускался и рендерил существующий NotebookApp/BlockNote с тестовым
документом: цитата, длинный список, код и два уровня вложенных пунктов. Это не скриншот
отдельной HTML-имитации. Проверены оба оформления, все указанные окна, отсутствие overflow,
настройка через UI, persistence после reload, три ширины и focus.
Отдельно прошли обновление между двумя вкладками, fallback неверного сохранённого значения
и переключение в памяти при ошибке записи localStorage. Полный повторный UI-прогон этапа 1.5
также прошёл: autosave/pending flush, поиск, избранное, навигация, настройки, resize,
mobile Back, имитация visualViewport клавиатуры, прокрутка кода и touch-компоновка.

Локальная среда не содержит настроенной БД или открытой пользовательской заметки. Поэтому
проверка именно пользовательского документа и серверный PostgreSQL E2E недоступны;
тестовые API-ответы не выдаются за production CRUD. Физический Fold/WebView не проверялся.
Исходные пользовательские данные, API, PostgreSQL, палитры, Docker/CI и Unraid не менялись.

`npm.cmd run check`: Android client contract, lint, typecheck, 269 unit tests passed,
36 skipped, production build — успешно. В `e2e/studio.spec.ts` добавлены регрессии геометрии
и выбора выравнивания для запуска с отдельной тестовой БД.

Изменённые файлы: `src/app/studio.css`, `src/components/notebook/document-alignment.tsx`,
`notebook-app.tsx`, `settings-dialog.tsx` в том же каталоге компонентов;
`src/lib/document-alignment.ts`, `src/lib/document-alignment.test.ts`, `e2e/studio.spec.ts`,
`docs/STUDIO_DESIGN_SYSTEM.md` и этот отчёт.
