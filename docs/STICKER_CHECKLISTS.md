# Чек-листы стикеров

## Аудит и хранение

QuickNote хранит обычный `body: String` (до 10 000 символов), без BlockNote. Sticker Board редактировал textarea, Quick Capture создавал стикер явным действием, «Сегодня» показывал текст внутри кнопки перехода на доску. Старый autosave имел один таймер на ID: изменение body могло отменить ещё не отправленный title; полный ответ PATCH заменял карточку и мог затереть более новый локальный ввод.

Использовано совместимое представление внутри того же body: строка `- [ ] Текст` или `- [x] Текст`, также читается `[X]`. В интерфейсе это checkbox и редактируемый текст, отдельного Markdown-редактора нет. Обычные строки и несколько списков могут перемежаться; пустые строки сохраняются. Ранее существовавшие строки такого вида распознаются при отображении, без перезаписи/миграции body. Чтобы оставить такой маркер буквальным текстом, можно поставить перед дефисом обратную косую черту.

Переключение изменяет один символ, сохраняя остальные строки, отступы, кириллицу и CRLF. Существующие обычные стикеры остаются textarea, пока пользователь не добавит чек-лист. Prisma schema, миграции и версии portable format не меняются.

## Использование

- Кнопка «Чек-лист» оформляет текущую строку; повторное применение возвращает обычную строку.
- Enter создаёт следующий пункт и переносит текст после курсора. Backspace в начале пункта снимает оформление, включая пустой пункт; обычная пустая строка позволяет продолжить заметку текстом.
- Пункты редактируются на месте. Выполненные зачёркнуты и приглушены. Нативный checkbox поддерживает Space и touch, зона нажатия не меньше 44×44 CSS px.
- Доска показывает компактный прогресс `done/total`, длинный редактор ограничен по высоте и прокручивается внутри карточки.
- На «Сегодня» preview содержит до пяти логических строк, общий прогресс учитывает весь стикер. Checkbox отделён от кнопки открытия; отметка не переводит на доску. Остальная карточка открывает существующий экран стикеров.
- Quick Capture использует тот же редактор, сохраняется прежней кнопкой создания либо Ctrl/Cmd+Enter. Отдельной кнопки Save для редактирования существующего стикера нет.

## Сохранение и конфликты

На один аккаунт/workspace создаётся StickerSaveStore, на ID стикера — один упорядоченный writer поверх существующего EditorSaveQueue. Title/body и действия карточки объединяются, а не отменяют друг друга. Текст имеет debounce 650 ms и flush при blur; checkbox начинает сохранение сразу. Пока есть более новый ввод, старый ответ не заменяет локальный черновик.

Store живёт над доской и «Сегодня», поэтому смена экрана не уничтожает таймер/очередь. Logout, logout-all, смена Android endpoint, дублирование, удаление и преобразование стикера ждут соответствующие записи. При уходе в фон выполняется flush; PATCH использует keepalive. Beforeunload предупреждает о dirty state как дополнительная защита. Принудительное завершение процесса до подтверждения сервера не объявляется гарантированно сохранённым; текст не копируется в localStorage.

PATCH `/api/quick-notes/:id` получил необязательные `expectedBody`/`expectedTitle`. Новый клиент всегда передаёт их. Внутри транзакции updateMany атомарно проверяет ID, ownership и прежний текст; несовпадение даёт 409, чужой/удалённый объект — 404. Старый формат PATCH по-прежнему принимается для совместимости. Это защита от stale writes, не новая система совместного редактирования.

Добавлен ownership-scoped GET `/api/quick-notes/:id`: он нужен для проверки результата при потере ответа. Если сервер уже содержит весь отправленный payload, запись считается подтверждённой; другое содержимое не становится базой для автоматического overwrite.

Ошибка оставляет черновик в памяти с действиями «Повторить сохранение стикера» и «Сохранить черновик копией». Копия создаётся существующим POST, оригинал не перезаписывается. Если пользователь продолжил печатать во время создания копии, более новый черновик не сбрасывается. Ошибка создания копии также видна. Статус «Сохранено» появляется после подтверждения сервером или проверочного чтения, а не после одного optimistic toggle.

## Экспорт, импорт, backup и преобразование

Portable export/import и application backup уже передают body строкой без преобразования, поэтому отметки сохраняются вместе с текстом в JSON/ZIP. Код этих форматов не менялся. Экспорт отражает подтверждённую серверную версию; перед проверкой нужно дождаться «Сохранено».

Явное преобразование стикера в Page создаёт штатные BlockNote `checkListItem` с `props.checked`; обычные строки остаются paragraph. Это действие пользователя, а не автоматическая миграция. Существующие Markdown/HTML exporters уже поддерживают такие BlockNote-блоки. Теги продолжают синхронизироваться тем же сервисом.

## Проверки

`npm run check` прошёл: lint, typecheck, production build; unit tests — **345 passed / 38 skipped**, 65 файлов passed / 11 skipped. Добавлены проверки parsing/CRLF/mixed lists, native BlockNote conversion, ordered writer/coalescing, stale replies, retry, изоляции account stores, изменений во время recovery copy, atomic ownership/text predicate и точного JSON round-trip portable body.

Chrome с настоящим Next.js App Router и синтетическим API проверил обе Studio-темы: быстрые отметки совместно с title/body, Enter/Backspace, reload, «Сегодня» без открытия карточки, Space, Quick Capture, network error/retry, потерянный ответ PATCH и конфликт с сохранением копии. Отдельный touch-контекст проверил taps, редактирование старого plain text и оформление существующей строки. Размеры — 1440, 393 и 840 px, без горизонтального overflow.

Добавлены PostgreSQL integration test stale/ownership/duplicate/convert и два E2E-сценария, включая реальный ZIP export→import. Они доступны в репозитории, но **не выполнены без выделенной PostgreSQL БД/Docker**; E2E только обнаружены через `playwright test e2e/sticker-checklists.spec.ts --list`. JSON round-trip выполнен локально. Браузерный стенд не заменяет проверку настоящего Prisma/route-handlers/ZIP lifecycle на БД.

Физический Fold и Android instrumentation недоступны. Скриншоты/результаты Chrome находятся в игнорируемом `test-results/sticker-checklists/`: `next-checks.json`, `touch-checks.json`, `next-*-board.png`. Использовались только синтетические данные.

Основные изменения: `sticker-checklist`, `sticker-save-store`, `quick-note` types, `sticker-body-editor`, `sticker-save-provider`; интеграция в `quick-notes`, `today-view`, `notebook-app`; условный update/read quick-note-service/API/schema validation; Today select; CSS, документация и тесты. Users/permissions, Docker, CI, Unraid и APK не менялись. Production не обновлялся.
