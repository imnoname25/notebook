# Studio Mobile UX: компоновка и приёмка на Fold

База аудита: `d1e7f0bc35c2515b70271ee8bd5275151d62108e`. Изменяется веб-интерфейс Studio,
а не Android APK или production deployment. Graphite/Atelier, модель документов,
API, PostgreSQL, Docker и CI не изменяются. DnD вкладок не дорабатывается.

## Подтверждённые причины

- `NotebookApp` раньше обрабатывал меню через `setMobileView("navigation")`. Правила
  `studio.css` для 768–1199 px заменяли две рабочие панели одной полноэкранной навигацией.
  Это был экран, а не drawer поверх остающегося на месте редактора.
- В `globals.css` мобильные `[data-density] .notebook-sidebar ...` задают минимум 56 px
  второй кнопке блокнота (фактически expander), 52 px разделам и 48 px остальным кнопкам.
  Вместе со Studio-правилами и `flex-1` у дерева это давало неодинаковую плотность и
  свободное место перед нижними действиями. На внутреннем viewport нижний блок был 185 px.
- `notebook-editor-header` использовал flex-wrap, title с полной шириной и `::before`
  для значка. В реальном DOM с page.icon значок занимал отдельную строку. Заголовок,
  статус и действие переменных вместе занимали 125–132 px даже без тегов/обложки.
- У BlockNote фактический DOM — `.bn-block-content[data-content-type="table"]` →
  `.tableWrapper` → `.tableWrapper-inner` → `table`. Одного overflow на внешнем блоке
  недостаточно: таблица сначала сжималась до доступной ширины. Три сохранённые колонки
  по 220 px на 393 px viewport становились примерно по 110 px. `word-break: break-word`
  затем разбивал технические значения и имена на короткие фрагменты.
- Шапка в текущей Chrome-базе **уже была 48 CSS px**, а не сотни CSS px. Однако её высота
  дополнительно включала safe-area-top, уже зарезервированный `.notebook-app-shell`.
  Удалён повторный учёт inset; новая высота 52 CSS px при стандартном размере шрифта.

`layout.tsx` задаёт device-width / initialScale 1 / viewportFit cover /
interactiveWidget resizes-content. WebView и viewport не изменялись; нет zoom,
transform scale, UA/model detection или глобального уменьшения шрифта.
Фактические Android fontScale, WebView version и CSS viewport устройства не считаны;
масштабирование ОС не объявляется доказанной причиной.

## Реализация

`WorkspaceNavigation` использует существующий Radix Dialog и **тот же NotebookSidebar**.
В Studio до 1200 px дерево монтируется в drawer по запросу, от 1200 px — в прежнем месте.
Нет второй реализации дерева или скрытой копии редактора. Dialog имеет имя, focus trap,
Escape, кнопку закрытия, возврат фокуса и связь aria-controls/expanded с кнопкой меню.
Android Back сначала закрывает drawer. Выбор destination закрывает его; существующие
save guards продолжают решать, можно ли переключить документ. Ошибка save сохраняет
текущий редактор. Контекстные меню/настройки открываются после закрытия drawer.

- До 768 px: последовательные список/редактор на всю ширину, компактный переключатель вкладок.
- 768–1199 px: список + редактор при выбранном разделе; sidebar только в drawer.
  «Режим фокуса» явно скрывает список и отдаёт редактору всю ширину.
- От 1200 px: прежний desktop. Legacy themes сохраняют свою навигационную модель.
- В drawer строки и кнопки минимум 44 px, нижние действия в двух колонках (около 93 px).
  Прокручивается всё тело drawer, поэтому длинное дерево или клавиатура не делают действия
  недоступными. Создание вложенного раздела остаётся в существующем контекстном меню.
- Мобильный header документа использует grid: значок рядом с title, статус под ним,
  переменные справа. Текст ошибки и повтор сохранения не скрываются.
- Только на мобильных Studio таблица сохраняет внутреннюю ширину; ячейки минимум 192 px,
  прокрутка на родном `.tableWrapper`. Его handles, contenteditable и сериализация BlockNote
  остаются прежними. Нет изменения JSON/columnWidths ради отображения.

## Проверки и скриншоты

- `npm run check`: lint, typecheck, 295 unit tests passed / 36 existing skips,
  production webpack build прошли. Android client contract/URL/build-info checks прошли.
- Реальный Chrome, UI с настоящими NotebookApp/BlockNote и изолированными in-memory API fixtures:
  обе темы, drawer/select/close/Escape/native Back, поиск/favorites/recent, Today/Stickers,
  templates/tags/trash/settings, create/open/save; редактирование ячейки и горизонтальный scroll.
  Отдельно проверены синтетические изображение/обложка на 393/840/1440 px.
- Вкладки: preview/permanent/pin, session reload, быстрые переключения с pending save,
  ошибка save/повтор/безопасное закрытие, history, account isolation, resize проходят.
- Клавиатура **имитировалась** через resize и отдельный visualViewport высотой 340 px:
  caret остаётся в видимой области. Проверены короткое окно 350 px, увеличение текста,
  reduced motion, DPR 2.75, искусственные safe-area 24/16 px и focus trap drawer.
- `e2e/studio-mobile.spec.ts` добавляет два PostgreSQL-backed сценария с реальными таблицами,
  порогами высоты, readable columns, drawer, save и focus. Playwright list/typecheck прошли;
  запуск этих DB-backed сценариев недоступен без отдельной E2E_DATABASE_URL и разрешённого reset.
  Production БД для тестов не использовалась. Fixtures не доказывают server CRUD/ownership.

Локальные артефакты (ignored, не включены в Git): `test-results/studio-mobile/`.
Парные screenshots: `before-studio-{graphite,atelier}-{outer,inner,desktop}.png` и
`after-studio-{graphite,atelier}-{outer,inner,desktop}.png`; для drawer добавлен
суффикс `-navigation`. Рядом before/after-metrics.json, checks.json и environment.json.
Скриншоты до/после сняты до тестовых правок с одинаковым содержимым.

Почему прежние Chrome-проверки пропустили проблему: проверка scrollWidth страницы проходит
и при сжатии таблицы до нечитаемых ячеек. Ранние документы не проверяли комбинацию page.icon
и длинной таблицы; не было пределов высоты header metadata и проверки поведения drawer.
Новые сценарии проверяют эти признаки отдельно. Это не доказывает тождество Chrome и Android.

## Проверка пользователем на физическом Fold

После отдельно выполненного пользователем обновления веб-приложения этим коммитом:

1. На внешнем экране в обеих темах открыть навигацию, раскрыть блокнот, выбрать раздел и заметку.
   Drawer должен закрыться, редактор занять ширину; нижние действия доступны прокруткой.
2. На тестовой заметке прокрутить таблицу из 3+ колонок в обе стороны, отредактировать ячейки
   первой и последней колонок, дождаться подтверждения autosave и переоткрыть документ.
3. В длинном документе открыть/закрыть клавиатуру в начале, середине и конце. Проверить курсор,
   списки, вложенные блоки, цитаты, код, изображение/обложку при наличии.
4. Открыть несколько вкладок, править первую, быстро переключиться, закрыть другую и перезапустить.
   Подтверждённые правки сохраняются; ошибка сети не должна молча закрывать dirty документ.
5. Раскрыть/сложить Fold, повернуть и проверить split-screen. Активная заметка и pending text
   должны остаться; при достаточной ширине видны список + редактор, focus скрывает список.
6. Проверить поиск, настройки, Сегодня/Стикеры, Back, системный размер текста и safe-area.

Физический Fold/Android WebView и настоящая IME **не тестировались**. Окончательная приёмка
остаётся за пользователем на устройстве. Production deployment и пересборка APK не выполнялись.

`src/components/notebook/notebook-app.tsx`, `mobile-app-header.tsx`, новый `workspace-navigation.tsx`,
`e2e/studio-mobile.spec.ts`, этот документ.
