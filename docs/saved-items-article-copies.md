# Локальные копии статей в «Сохранённом»

## Предлагаемый сценарий

Пользователь сохраняет ссылку как обычно и по желанию запускает действие «Сохранить копию статьи». Когда копия готова, «Читать копию» открывает текст и сохранённые изображения с сервера Notebook. «Открыть источник» остаётся доступным. Чтение переживает недоступность исходного сайта. Чтение без связи с сервером Notebook потребует отдельного клиентского кэша и решения о его защите и очистке при смене аккаунта.

## Извлечение и хранение

1. Запускать отдельное идемпотентное задание по образцу очереди метаданных в монолите Next.js. Проверять владельца при запуске, чтении и удалении. Фиксировать URL и ревизию задания, чтобы поздний результат не восстановил удалённую копию или копию предыдущего URL.
2. Загружать только публичный HTML штатным транспортом с проверкой и закреплением адреса на каждом переходе. Задать бюджеты на время, размер ответа, число DOM-узлов, количество изображений и общий объём копии. При HTTP 401, 403 или недоступном тексте показывать результат задания в материале. Ссылка остаётся доступной.
3. Проверить Mozilla Readability на выборке статей с разной разметкой и языками. Парсить в инертном DOM без выполнения JavaScript и автоматической загрузки ресурсов. Извлекать заголовок, основной текст, заголовки разделов, списки, цитаты и подписи к изображениям. Измерять долю мусора и потери значимых частей текста. [Mozilla Readability](https://github.com/mozilla/readability/blob/main/README.md)
4. Проецировать результат в версионированный набор разрешённых блоков и проверять его схемой. Рендерить текст через React. Сохранять ссылки после проверки схемы URL. Скрипты, стили, формы, iframe, обработчики событий и неизвестные элементы отбрасывать. Если понадобится HTML, потребуется независимая очистка по списку разрешённых элементов и атрибутов и ограничительная CSP.
5. Загружать изображения отдельно через тот же защищённый транспорт с проверкой фактического формата и размера. Разрешить ограниченный набор растровых форматов. Хранить файлы в persistent `/data/uploads`, выдавать через аутентифицированный API с проверкой владельца. В копии использовать только локальные ссылки на эти файлы. При частичном сбое сохранить текст с доступными изображениями.
6. Хранить копию и версию формата в PostgreSQL, связав их с записью «Сохранённого». Удалять промежуточные файлы после сбоя и при отмене записи результата. Включить структурированный текст и локальные изображения в совместимый export/import и backup. Проверить восстановление из PostgreSQL dump и каталога uploads.

## Риски и критерии пилота

| Риск | Как проверить или ограничить |
| --- | --- |
| Защита источника, динамический HTML, страницы без текста | Измерить долю успешно извлечённых статей. Проверить, что ссылка остаётся рабочей при отказе и что задание не сохраняет страницу входа вместо статьи. |
| Ошибки извлечения | Сравнить сохранённые заголовки, абзацы, подписи и порядок блоков с оригиналами. Включить в выборку страницы с рекламой, меню и несколькими колонками. |
| Активное содержимое и сетевые обращения | Проверить схему блоков, выдачу изображений с ownership, отказ на запрещённых URL и отсутствие запросов к исходному сайту при чтении копии. |
| Рост диска и нагрузка на single-instance | Ограничить параллелизм, байты, время и число изображений. Проверить очистку частичных и удалённых копий и восстановление после перезапуска. |
| Условия копирования контента | До пилота определить допустимые источники и условия хранения. Проектировать копии для личного чтения внутри аккаунта. |

Первый пилот стоит ограничить публичными статическими статьями и запуском по запросу пользователя. Полноценное извлечение статей требует отдельного продуктового согласования.
