# Studio Search 3.1 — Unified Live Search

## Аудит исходного состояния

Исходная версия — `57a18b6`. `DesktopAppHeader` уже содержал кнопку поиска, но Studio CSS размещал её во второй колонке titlebar, привязанной к ширине списка документов. Поэтому на самостоятельных экранах кнопка выглядела частью отсутствующей панели документов. `SearchDialog` совмещал cmdk quick switcher, поиск, недавние/избранное и команды с префиксом `>`, показывая modal overlay. `Ctrl/Cmd+K` открывал этот диалог.

`GET /api/search` использовал общий `searchNotebook`: generated tsvector/GIN для Page, Section, Notebook; `websearch_to_tsquery('simple', ...)`; приоритет заголовков; title substring fallback; `ts_headline` и безопасные текстовые highlight parts. Запрос был ограничен 300 символами, страница выдачи — 25 объектами, offset — 250. Фильтров не было. Отдельная Prisma-ветка `#тег` объединяла страницы и Inbox-стикеры, но возвращала `nextOffset: null` и предварительно ограничивала коллекции. Существующие индексы хештегов синхронизируются через page-service save/restore/import lifecycle.

Навигация документов использует `/pages/:id`, native History API и `useDocumentTabs`. Переходы должны проходить через `tabs.leave`/`openPageById`, которые ждут pending autosave. Прямое переключение `screen` до flush могло бы размонтировать редактор с несохранёнными изменениями — этот путь не используется для открытия поиска.

## Итоговый интерфейс

- Общая кнопка поиска находится в titlebar независимо от desktop-ширины списка. Её положение одинаково в редакторе, «Сегодня», «Стикерах», избранном и недавних. Палитры Studio не меняются.
- Search View — самостоятельный `screen="search"`, sidebar + выдача на desktop, одна рабочая панель на мобильном. Списка документов, редактора и desktop-разделителей на этом экране нет. Drawer остаётся доступен по запросу.
- Поле ввода постоянно видно. Результаты содержат заголовок, notebook/section, безопасный фрагмент/подсветку и дату изменения. Длинный preview ограничен двумя строками.
- Фильтры раскрываются компактной кнопкой: notebook, section, один тег, даты от/по. При смене блокнота выбранный раздел сбрасывается. «Избранное» и «Недавние» — варианты той же выдачи с серверным фильтром.
- Клики по хештегам редактора/«Сегодня»/«Стикеров» и выбор тега из списка открывают Search View. Список тегов остаётся доступен из навигации.
- Командная палитра теперь содержит только прежние команды. Поисковая выдача в неё не дублируется.

## Навигация и данные

Адрес поиска: `/app?view=search&q=...` с необязательными `notebookId`, `sectionId`, `tag`, `dateFrom`, `dateTo`, `group`. Открытие создаёт одну запись истории, ввод/изменение фильтров заменяет текущую запись. Каждая буква не создаёт отдельного шага Back. Запрос не записывается в localStorage, содержимое документов не входит в состояние поиска. Состояние компонента принадлежит текущему account workspace; смена аккаунта размонтирует его.

Выбор страницы вызывает существующий `openPageById`, создаёт/активирует вкладку без дубликатов и сохраняет deep links. Back возвращает URL запроса/фильтров, Forward снова открывает документ. Кнопка возврата ведёт к предыдущему экрану; для прямого входа в URL без предыдущего внутреннего перехода используется workspace. «Сегодня»/«Стикеры» также имеют различимые URL (`view=today/stickers`), чтобы не терять экран возврата. Notebook/section results открываются через существующие обработчики с сохранением записи поиска в истории.

Восстановление вкладок получило необязательный флаг `activate=false`: прямая ссылка на Search View/самостоятельный экран восстанавливает метаданные постоянных вкладок, но не открывает последнюю заметку поверх URL. Настройка стартового экрана также не заменяет явный destination. Содержимое заметок и протокол сохранения не меняются.

Открытие поиска сначала ждёт `tabs.leave`/flush. Ошибка сохранения оставляет редактор и текст на месте; история поиска ещё не создана. Повторная попытка использует существующее действие autosave. При Back из документа flush тоже выполняется до размонтирования редактора. При неудаче существующий механизм вкладок возвращает URL текущего документа.

## Живой запрос и API

Debounce — 200 ms. Каждый запрос имеет AbortController и порядковый номер; перед изменением ответа проверяются оба. Отображение дополнительно привязано к ключу текущих query/filters: старые результаты исчезают сразу после изменения ввода, до ответа нового запроса. «Показать ещё» использует тот же abort signal и guard, не добавляет повторные ID.

Пустая строка без фильтров не загружает библиотеку. Для текста нужно минимум два символа; пустой query с фильтром допустим. Максимальная длина — 300 символов. API сохраняет `results`/`nextOffset`, добавляет optional ISO `updatedAt`, принимает новые параметры без миграций.

Фильтры выполняются в существующем search-service. Page/Section/Notebook продолжают использовать generated vectors/GIN. Теги используют существующие PageTag/QuickNoteTag/Tag, без клиентского ownership. В каждой ветке SQL проверяется userId; удалённые страницы, разделы, блокноты и архивные стикеры исключаются. Чужой notebook/section filter даёт пустую выдачу. SQL и фильтры parameterized; `Prisma.raw` используется только для постоянных внутренних highlight markers. React выводит текст через span/mark, без `dangerouslySetInnerHTML`.

Текстовый поиск включает Inbox-стикеры; они не привязаны к notebook/section и исключаются при соответствующих фильтрах. `#тег` и тег-фильтр работают в общей пагинируемой выдаче. Два разных заданных тега пересекаются. Favorites/recent применимы к страницам; recent сортируется по существующему RecentPage.lastOpenedAt. Даты изменения интерпретируются как UTC-дни, верхняя граница включительна.

## Клавиатура и адаптивность

`Ctrl/Cmd+K` — поиск и фокус ввода; `Ctrl/Cmd+Shift+P` — команды; стрелки в поле/выдаче — выбор; Enter — открытие; Esc — снятие фокуса. Select/date/tag controls сохраняют свои клавиатурные действия. Системные сочетания работают, только если браузер доставляет событие приложению. Обычные действия BlockNote, форматы документов и save queue не переписываются.

На ширинах Studio менее 1200 px поиск занимает всю рабочую область, навигация открывается drawer. Desktop-настройки панелей не задают его ширину. Проверены 393 и 840 px, изменение высоты до 400 px с фокусом в строке; это моделирование клавиатуры/доступного viewport, не физическая клавиатура Android и не аппаратное складывание.

- Локальные Chrome-сценарии через настоящий Next.js App Router прошли в обеих темах: stale response, очистка/длинный/пустой запрос, выдача 25+15, фильтры, Enter, команды, history/reload, оба самостоятельных экрана, autosave. Дополнительная проверка: failed save не пускает в поиск; retry сохраняет текст; tags переходят в Search View; прямой URL побеждает Today preference и session restore; desktop widths не влияют на mobile; JS Android Back возвращает предыдущий экран.
- Реальный search-service отдельно исполнен на временном embedded PostgreSQL ([PGlite](https://pglite.dev/docs/)): SQL/FTS/ranking/highlights, ownership/trash, notebook/section/tag/date/favorites/recent, стикеры, pagination и SQL injection input. Инструмент установлен только в ignored cache, зависимости продукта не меняются.

Полноценный PostgreSQL E2E с настоящими route handlers/auth и Prisma недоступен: нет выделенной тестовой БД/Docker. 37 соответствующих интеграционных проверок пропущены, а не объявлены успешными. Next.js-стенд использует синтетический API для документов и search-service на embedded PostgreSQL для поиска; это не production backend. Физический Fold не подключён, APK не менялся.

Локальные скриншоты и отчёты: `test-results/search-3-1/index.html`, `before-*.png`, `next-*-search-{1280,1440,1920,outer,inner}.png`, `next-checks.json`, `extras-checks.json`. Исходные и новые сцены используют синтетические заметки, без реальных секретов. В gallery отдельно обозначены старый modal quick switcher и новый Search View.

## Ограничения

Автоматический переход к конкретному совпадению внутри BlockNote пока не реализован: выдача FTS не содержит стабильного blockId. Поиск не меняет выделение/содержимое редактора ради приблизительного совпадения. Страница открывается обычным механизмом вкладок.

Серверный cap offset 250 сохранён: при размере 25 доступно до 275 результатов, затем интерфейс предлагает уточнить запрос. Это ограниченная выдача, не обещание полного total count. Вводимый запрос и фильтры входят в URL/history; приложение не добавляет журналов запросов, аналитики или логирования фрагментов заметок.

У QuickNote нет отдельного GIN-индекса, поэтому текстовый поиск по Inbox вычисляет vector в user-scoped ветке запроса. Для очень большого Inbox производительность требует отдельного измерения; миграция на этом этапе не добавлялась. Выбор стикера открывает существующий экран «Стикеры», без нового отдельного редактора стикеров.

Изменены UI (`search-view`, `use-workspace-search`, командная палитра, интеграция NotebookApp/TagBrowser), `search.css`/CSS import, search API/service/validation, mobile Back type, опция восстановления вкладок, README и тесты. Docker, CI, Unraid, Android APK, Prisma schema, миграции, формат документов и production deployment не изменялись.
