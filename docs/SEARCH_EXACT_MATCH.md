# Search → переход к совпадению (дополнение Studio 3.3)

## Аудит и границы интеграции

Notebook использует BlockNote 0.54, ProseMirror state/view и собственную обратно совместимую схему блоков. `/api/search` возвращает заголовок, snippet и подсветку, но не blockId или позицию внутри документа. Открытие результата уже проходит через вкладки, последовательную очередь переходов и flush autosave. Эти механизмы сохраняются.

Проверены установленный `BlockNoteExtension.ts` и публичные `prosemirrorView` / `prosemirrorState`. Подсветка реализована штатным расширением с `prosemirrorPlugins` и inline decorations, а не изменением HTML или BlockNote JSON. См. [BlockNote extensions](https://www.blocknotejs.org/docs/features/extensions) и [ProseMirror: plugin state, decorations и history metadata](https://prosemirror.net/docs/guide/).

## Поведение

Быстрый и расширенный поиск передают выбранной странице текущий запрос и snippet. После успешного открытия вкладки и подключения именно её ProseMirror view вычисляются совпадения. Счётчик запроса и существующая очередь переходов отбрасывают устаревшие открытия. Если сохранение не удалось, новая цель подсветки не устанавливается.

Сначала выбирается текстовый блок, лучше всего соответствующий контексту серверного snippet. При равном контексте выбирается первое совпадение. Без серверной позиции нельзя отличить два полностью одинаковых фрагмента; между ними можно перейти навигатором. Это не обещание точного server offset, которого API не предоставляет.

Диапазоны вычисляются по ProseMirror textblock, включая смещения UTF-16 и inline atoms. Совпадение может пересекать границу форматирования внутри одного текстового блока. Поддерживаются абзацы, заголовки, списки, цитаты, код, ячейки таблиц, inline-содержимое Callout и доступные текстовые дочерние блоки. Для обычных слов используется регистронезависимое начало слова, согласованное с prefix FTS; в заголовке страницы поддерживается также substring fallback. Кавычки сохраняют цельную фразу, OR и отрицательные слова не подсвечиваются как положительные термины. Это локальная навигация по уже найденной странице, не второй поисковый API.

Навигатор «Совпадение N из M» размещён отдельной компактной строкой перед прокручиваемой областью текста. Он не перекрывает вкладки или документ. Стрелки обходят совпадения циклически, включая заголовок страницы. При переключении выполняется прокрутка к активной inline decoration; для reduced motion используется мгновенная прокрутка. При изменении текста список пересчитывается, исчезнувшее совпадение не вызывает ошибку.

Если совпадение только в названии страницы, подсвечивается соответствующая часть названия без прокрутки содержимого. Поскольку input не поддерживает inline decorations, используется текстовое зеркало над прежним controlled input, скрытое от accessibility tree. При редактировании названия зеркало скрывается, input сохраняет обычную работу. Подсветка повторяется после снятия фокуса. Изменение числа совпадений во время редактирования не заменяет input.

Активный путь в свёрнутых группах временно раскрывается node decorations и CSS. Сохранённые `open` props и состояние документа не переключаются. При закрытии навигатора inline/node decorations, зеркало и навигатор исчезают; закрытая группа возвращается к прежнему отображению.

Atelier использует прозрачный тёплый янтарный фон, Graphite — отдельные прозрачные золотистые оттенки. Активное совпадение заметнее и имеет спокойную нижнюю линию. Основные палитры Studio не изменялись. Анимации мигания отсутствуют.

## Сохранность данных

Команды подсветки — транзакции только с metadata и `addToHistory=false`. Они не меняют `doc`, selection или форматирование. Подсветка не входит в JSON, undo history, экспорт или БД. Существующий fingerprint guard autosave дополнительно защищает от лишних сохранений. Закрытие навигатора не закрывает документ, а обычная вкладка повторно используется.

Содержимое не сохраняется в localStorage. В памяти интерфейса находится только текущий запрос/цель перехода; формат пользовательских документов и API не менялись.

## Размеры стикеров

Существующая реализация 3.3 уже хранит размеры по паре userId/noteId. Подтверждено: изменение первого стикера не меняет второй, сброс второго не сбрасывает первый, reload и возврат того же аккаунта восстанавливают индивидуальные размеры. Смена аккаунта использует другие ключи. Logout не удаляет эти presentation preferences. Ниже desktop breakpoint размеры только игнорируются, не перезаписываются. Существующие стикеры без валидной записи получают стандартные 320×340 px. Размеры локальны для браузера; синхронизации между устройствами нет.

## Известные ограничения

- Максимум 3000 текстовых совпадений в документе; при достижении лимита счётчик показывает `+`.
- Фраза не пересекает границы разных блоков или ячеек. Поиск не добавляет стемминг, regex или fuzzy matching.
- Метаданные в props, включая отдельное поле заголовка Callout, подписи изображений, вычисляемые значения Live Widget и неподдерживаемые блоки, не получают ProseMirror-подсветку. Для read-only несовместимого документа остаётся существующее предупреждение/экспорт. Совпадения в обычном inline-содержимом Callout поддерживаются.
- У полностью одинаковых snippet-контекстов нет надёжного server offset: выбирается первый равный, остальные доступны стрелками.
- Title mirror скрывается на время редактирования названия, чтобы сохранить native input и выделение текста.
- Chrome viewport не является проверкой Android WebView/клавиатуры; физический Fold требует проверки пользователем.
